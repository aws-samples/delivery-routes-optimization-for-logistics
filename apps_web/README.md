# Delivery Route Optimization — Web App

Web UI for the delivery route optimization project, built on React 19 + Vite + pnpm.
It connects to the CDK-provisioned backend (Cognito / API Gateway / S3-CloudFront) to
manage Warehouses / CustomerLocations / Vehicles / Orders / DistanceCache / SolverJobs
and visualizes optimization results on the map.

## Running Locally

### Prerequisites

1. Install Node.js ≥ 20.19 and pnpm ≥ 9
2. Provide a `public/static/appvars.js` that points at the deployed backend.

   - **Option A — pull the file generated by CDK (recommended)**
     If `apps_infra` has already been deployed, the S3 website origin already has
     `/static/appvars.js`. Use `apps_infra/scripts/pull-appvars-js.sh` to fetch it
     for local development.

     ```bash
     # run from apps_infra (requires AWS_PROFILE / AWS_REGION)
     cd ../apps_infra
     ./scripts/pull-appvars-js.sh
     # then copy the pulled file into apps_web
     cp path/to/pulled/appvars.js ../apps_web/public/static/appvars.js
     ```

   - **Option B — author it by hand**
     Fill the file with the CloudFormation outputs printed after deployment.

     ```js
     // apps_web/public/static/appvars.js
     const appVariables = {
       REGION: 'us-east-1',
       USERPOOL_ID: 'us-east-1_xxxxxxxxx',
       USERPOOL_CLIENT_ID: 'xxxxxxxxxxxxxxxxxxxxxxxxxx',
       API_URL: 'https://xxxxxxxxxx.execute-api.us-east-1.amazonaws.com/prod/',
     }
     ```

   > `appvars.js` is gitignored. In production the CDK deployment pipeline uploads
   > it to S3 automatically.

## Runtime Variables (`appvars.js`)

| Key | Description |
| --- | --- |
| `REGION` | AWS region (for example `ap-northeast-2`) |
| `USERPOOL_ID` | Cognito User Pool ID |
| `USERPOOL_CLIENT_ID` | Cognito User Pool Client ID |
| `API_URL` | API Gateway base URL (`/api/web` is appended automatically) |

`src/config/appvars.ts` validates each key and raises a descriptive error if any
is missing at runtime.

## API Layer

- `src/services/base/amplify.ts` — Amplify v6 initialization and the `getAuthHeaders()` helper
- `src/api/Common.ts` — shared REST wrapper (injects the Cognito ID token on every call)
- `src/services/base/crudService.ts` / `queryService.ts` — per-resource CRUD / Query abstractions

Because Amplify v6 removed the configuration-level `custom_header` callback, the
token is fetched via `getAuthHeaders()` at each call site and passed through the
request `options.headers`.

## Cloudscape UI Notes

- The global stylesheet (`@cloudscape-design/global-styles/index.css`) is imported once from `main.tsx`.
- Pages use a `TopNavigation` + `AppLayout` (`navigation` / `breadcrumbs` / `content` slots) layout.
- Tables use `Table` + `columnDefinitions` (id / header / cell / sortingField); in-page navigation is handled through the `Link` component's `onFollow` callback which forwards to `navigate()`.

## Routing

- `react-router-dom` v7 with `<BrowserRouter>` + `<Routes>` + `<Route element={...} />`
- Each section owns its subtree under `src/pages/<Section>/router/index.tsx`
- Programmatic navigation uses the `useNavigate()` hook

## Map

- Built on `react-map-gl` v8 via the `/maplibre` entry (`react-map-gl/maplibre`) + `maplibre-gl` v5.
- Tiles and styles come from [OpenFreeMap](https://openfreemap.org) (`https://tiles.openfreemap.org/styles/liberty`), so **no API key is required**.
- View state is managed with `initialViewState` + `onMove`.
- Custom markers combine the `<Marker>` wrapper with inline SVG (`src/components/MapPin`).
- `@mapbox/polyline` is used to decode polyline-encoded path strings (network-free utility, unrelated to Mapbox accounts / tokens).
